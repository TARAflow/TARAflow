# Manual test: EN 50742 Approaches A and B

## Purpose

This guide tests the EN 50742 support of 0.20 by hand:

- the tag rules: one base method, Approach A as an addition, exclusions;
- the safety zone and the EL badges in the diagram;
- the EN 50742 relevance of risks;
- Approach A with the standard method and with ETSI TVRA;
- Approach B and its requirement matrix;
- the report.

Run it before every release that touches EN 50742, the tag editor, the DFD badges or
the risk calculation.

The test also creates the two example projects of the examples repository, see
[Saving the examples](#9-saving-the-examples). Mark every step **OK** or **Deviation**
(see [Reporting](#reporting)).

## Prerequisites

- TARAflow desktop app (Electron) or the browser build.
- The `TARAflow_Examples` repository checked out.

### Test data

Start from `TARAflow_Examples/Simple_Test_Project.tara.json`. Copy it to
`EN50742-A-SafetyZone.tara.json`, and work only on the copy.

| Element | What it is |
|---|---|
| `MTB` My Trust Boundary | Trust boundary, default EL1. Becomes the safety zone. |
| `IF-1` USB, `IF-2` JTAG | Interfaces, EL1 |
| `DB` Device Boundary | Physical boundary, PEL2 |
| `STM` STM32F4 | Chip boundary, default EL1 |
| `P-1` MyProcess, `DS-1` Flash | Process and store inside `MTB` |
| `EE-1` MyExternal, `EE-2` Debugger | External entities |
| `DF-3` push control command (EE-1 → P-1), `DF-2` write config data (P-1 → DS-1), `DF-4` push register data (EE-2 → STM) | Data flows |

The project has the tags *IEC 62443* and *EN 50742 A* and the window of opportunity
*moderately restricted*.

## 1. Tags — one base method, A as an addition

Overview → Project information → Edit → Tags.

| # | Step | Expected |
|---|---|---|
| 1.1 | Add *ETSI TVRA*. | Added next to *EN 50742 A*. No red conflict line. |
| 1.2 | Add *ISO 21434*. | *ISO 21434* replaces *ETSI TVRA* and *EN 50742 A*. A blue line names both. |
| 1.3 | Cancel the edit. | The tags are as before. |
| 1.4 | Add *EN 50742 B*. | B replaces A. The blue line says "EN 50742 B replaces EN 50742 A". *IEC 62443* stays and is not added twice. |
| 1.5 | Cancel. Type the free tag `EN 50742` and press Enter. | Not added. The blue line asks to choose A or B. |
| 1.6 | Type `EN50742_A` and press Enter. | Nothing changes: *EN 50742 A* is already there. |
| 1.7 | In a scratch project: add *EN 50742 B*, then remove *IEC 62443*. | An amber hint says that B needs an IEC 62443-4-2 edition. Adding *EN IEC 62443 (CRA)* removes the hint. |

Cancel the edit, so the copy keeps *IEC 62443* + *EN 50742 A*.

## 3. Relevance of the risks (Approach A, standard method)

Risks tab. If the threats are not generated yet, generate them on the Threats tab first.

| # | Step | Expected |
|---|---|---|
| 3.1 | Open a risk on `DF-3` or on `IF-1` USB. | The risk dialog shows the EN 50742 section with EL (derived), attacker capability and SRSL. A relevance line names the zone. |
| 3.2 | Rate the attacker capability. | An SRSL appears. R = L × I does not change. |
| 3.3 | Open a risk of `P-1` or of `DF-2` (inside the zone). | Hint "Not EN 50742 relevant — …". No EL / AC / SRSL. R = L × I as usual. |
| 3.4 | Rate the attacker capability on **every** relevant risk. | Every relevant risk has an SRSL. *(Data for the SRSL 0 guard, 0.20 item 7.)* |

## 5. Approach A with ETSI TVRA

| # | Step | Expected |
|---|---|---|
| 5.1 | Save, and keep a copy of the file as it is now (for section 6 and the examples). Then add the tag *ETSI TVRA*. | No conflict line. Risks tab: the configuration shows the TVRA method. |
| 5.2 | Open the risk of 3.2. | Likelihood factors of TVRA (time, expertise …). The EN 50742 section with EL / AC / SRSL is still there, and the SRSL is unchanged. |
| 5.3 | Rate the TVRA factors. | R = L × I follows TVRA. EL and AC do not change R. |

| 5.6 | Add *EN 50742 A* again, then remove *ETSI TVRA*. | Removing TVRA warns again (its factors' ratings). Back to the standard method: EL is derived again, AC must be rated again (5.5 deleted it), then the SRSLs are back. |

## 6. Approach B

Copy the file kept in 5.1 (state after section 4) to `EN50742-B-SafetyZone.tara.json`.

| # | Step | Expected |
|---|---|---|
| 6.1 | Replace *EN 50742 A* with *EN 50742 B* and save. | The rating dialog warns (EL and AC ratings are deleted); confirm. B replaces A, and *IEC 62443* stays. The WoO selector disappears. The safety zone and the badges stay. |

## 9. Saving the examples

After a run without deviations, save both projects (badges on, settings as in the test)
into the examples repository and commit them there:

| File | Content |
|---|---|
| `en50742/EN50742-A-SafetyZone.tara.json` | The file kept in 5.1: Approach A, standard method, safety zone `MTB`, AC rated on every relevant risk, `DS-1` with audit records |
| `en50742/EN50742-B-SafetyZone.tara.json` | Approach B on the same model |

Add both to the overview table of the examples `README.md`. The results dump reference
gets them in the next release folder of `doc/Testing/results-dump/`.
