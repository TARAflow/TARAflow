## 1. Differences to the CRA edition (prAA)

| Topic | 2019 | prAA | Consequence for the matrix |
|---|---|---|---|
| Component types | CR = common to all; **SAR** software application, **EDR** embedded device, **HDR** host device, **NDR** network device (Clauses 12–15) | CR only, applicability per requirement | the classic matrix needs the **device category** of the component (§2, K-C1) |
| Device-specific CRs | CR 1.6, 1.13, 2.4, 2.13, 3.2, 3.10–3.14, 5.2, 5.3 exist only as SAR / EDR / HDR / NDR | all are CRs | one evidence mapping per CR number, applied to the device row that matches the category |
| Requirements only in 2019 | CR 1.7 RE(1) password generation / lifetime for humans (SL 3); CR 1.9 RE(1) hardware protection of long-lived private keys (SL 3); CR 1.14 symmetric-key authentication + RE(1) hardware protection (SL 2 / 3); CR 3.3 security functionality verification + RE(1) during normal operation (SL 1 / 4); HDR 3.2 RE(1) report version of code protection; NDR 5.3 person-to-person communication restrictions | void or "no component requirement" | rows exist only here |
| Requirements only in prAA | — | CR 7.9 component reset; CR 2.8 RE(1) audit opt-out; CR 3.10 RE(2) automatic updates; CR 4.1 RE(1) at rest; CR 3.12 / 3.13 / 3.14 as CRs for software too | rows exist only in the CRA matrix |
| CR 4.1 | one requirement: confidentiality at rest (where read authorization exists) **and** in transit | base = over external interfaces, RE(1) = at rest / processing | 2019 row needs both evidence parts |
| CCSC 2 | compensating countermeasures | supporting measures | same mechanism in the evaluator (D-5, D-7); the label follows the edition |
| SL-C selection | x.y.4 lists + Table B.1 | x.y.4 lists + Table A.1 | same rule (D-2) |
| CRA reference | none | Annex ZZ | no CRA column here |

## 2. Device category of the component (classic only)

The 2019 edition applies SAR / EDR / HDR / NDR rows by the component's type. The
component under evaluation is the selected element (D-7); its category is derived, the
analyst can override it (stored with D-8).

| Component (D-7) | Derived category | Rationale |
|---|---|---|
| Multiprocess `systemClass` ∈ embedded_controller, safety_system — or the component contains a ChipBoundary | **embedded device (EDR)** | firmware on dedicated hardware |
| Multiprocess `systemClass` = gateway | **network device (NDR)** | zone boundary device |
| Multiprocess `systemClass` ∈ scada_hmi, workstation, mobile_device | **host device (HDR)** | general-purpose OS host |
| Multiprocess `systemClass` ∈ backend_application, cloud_platform; a Process selected as component | **software application (SAR)** | software without own hardware |
| nothing selected / no `systemClass` | ask (no device rows evaluated until set) | — |

Several categories at once (e.g. an embedded device that also routes) are allowed by the
standard; the override is a multi-select.
