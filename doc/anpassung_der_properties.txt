# PhysicalProtection → Exposure Level (EL) Mapping für EN 50742

## 1. Lookup-Tabelle statt Array

Vorteile:
- Jede `physicalProtection`-Maßnahme hat direkt einen EL-Wert.
- Das Tool kann den niedrigsten EL auswählen, wenn mehrere Maßnahmen gleichzeitig aktiv sind (Defense-in-Depth-Prinzip).

```ts
export type PhysicalProtectionType =
  | "none"
  | "tamper_evident_seal"
  | "locked_cabinet"
  | "rack_enclosure"
  | "fenced_area"
  | "secure_area"
  | "biometric_lock";

export const PhysicalProtectionMapping: Record<PhysicalProtectionType, number> = {
  none: 4,                 // Public/Open
  tamper_evident_seal: 3,  // Nur Entdeckung, kaum Hinderung
  locked_cabinet: 2,       // Restricted Access
  rack_enclosure: 2,       // Gleichwertig zum Cabinet
  fenced_area: 1,          // Controlled Area
  secure_area: 1,          // Überwachter Bereich
  biometric_lock: 1        // High Security
};
```


2. Ableitungs-Logik (Derivation Engine)
- Physical: Prüfe alle gewählten Maßnahmen → wähle den niedrigsten EL (stärkste Schutzmaßnahme).
- Logical: Berücksichtige accessControl-Parameter wie MFA, Authentifizierung etc., die EL oder AP ggf. weiter senken.
- Boundary: Setze Minimum-EL für Interfaces an unsicheren Grenzen (z. B. Internet) → verhindert unrealistische Werte.

```ts
function deriveExposureLevel(measures: PhysicalProtectionType[]): number {
  return Math.min(...measures.map(m => PhysicalProtectionMapping[m]));
}

// Beispiel
const el = deriveExposureLevel(["locked_cabinet", "tamper_evident_seal"]); // EL = 2
```

3. EN 50742-konforme Reporting-Logik
- Dein Tool kann automatisch begründen, warum EL 2 gewählt wurde:
- >"Dataflow DF_01 hat EL 2, da Interface IF_USB über locked_cabinet verfügt (Mapping gemäß System-Konfiguration)."
- Auditorenfreundlich: Keine Interpretation nötig, alles reproduzierbar.

4. Defense-in-Depth
- Mehrere Maßnahmen wirken kumulativ → das Tool wählt automatisch den besten Schutz, der den EL bestimmt.
- Kein Array mit komplizierter Logik nötig → Lookup-Tabelle + Min-Funktion reicht.

💡 Fazit:
- Lookup-Tabelle + Min-Logik = sauber, wartbar, EN 50742-konform.
- Array von Objekten mit EL ist unnötig, würde nur Komplexität bringen.
- Dein Tool kann damit automatisch Exposure Level → Attack Potential → Risiko ableiten.
