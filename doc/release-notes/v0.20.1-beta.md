## TARAflow 0.20.1-beta

Small release after 0.20.0-beta: git over SSH no longer waits on a hidden prompt, the audit's SSH key path is checked, and the risks tab gets a filter by implementation status.

> No new project schema (still **14**): projects of 0.20.0-beta open unchanged, results stay the same, and 0.20.0-beta still opens files saved by 0.20.1-beta.

### Added

- **Risks tab — filter *Implementation*:** next to priority and risk level. A status (open, in progress, in review, implemented, verified, rejected) lists the risks whose *Implementation* column shows it — a risk with an open and an in-review mitigation is *in review*. Besides: *no mitigation selected*, *mitigations not done* (every risk with open work), *all mitigations done* and *done without evidence* (a done status without ticket, evidence note or reference — also without a tracker). The *won't* table is not filtered.

### Fixed

- **Git over SSH no longer hangs:** started from a terminal, *Resolve* of a source reference (also an audit push or the component check's fetch) to a host without a usable key asked for a password in that terminal, and TARAflow waited until its timeout. ssh now runs in batch mode and fails at once. *Resolve* says what to do: confirm a new host's key once in a terminal, or load a key with a passphrase into the ssh-agent (`ssh-add`). Your own ssh setup (`GIT_SSH_COMMAND`, `GIT_SSH`, `core.sshCommand`) is used as it is.
- **SSH key path of the audit settings checked:** the public key (`….pub`) was accepted as the SSH key, and ssh then fell back to a password prompt. The field now says what the path names — no file, a public key (the private key beside it is offered with one click), no private key, or readable by other users — and the type of a usable key. The key file's content never leaves the main process.
- **Where *Resolve* takes its SSH credentials from:** a source reference with an SSH URL is resolved with your SSH setup (`~/.ssh/config`, ssh-agent), not with the SSH key of the audit settings — said under the URL field and after a refused access; for Azure DevOps hosts with its key rules (RSA keys only, keys expire, stored per organisation).
- **Risk table — column widths:** the treatment column no longer grows with the table, and the headers *Risk (Before)* / *Risk (After)* no longer run into the next column (in German they are longer); every column is at least as wide as its header.

### What changes for you

- **A push with an unusable SSH key stops** with the reason (no file, public key, no private key, readable by others). Before, an invalid path was skipped silently and the push ran with your default key. Fix the path in the audit settings — the field shows what is wrong.
- **A Resolve over SSH that used to wait** now fails at once with a hint. A host never connected to before: run `ssh -T git@<host>` once in a terminal and confirm its key. A key with a passphrase: load it into the ssh-agent.
