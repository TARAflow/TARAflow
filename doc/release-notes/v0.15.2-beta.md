## TARAflow 0.15.2-beta

Security fix for the issue-tracker integration.

> No new project schema — projects stay on **schema 10** and open in 0.15.0-beta and 0.15.1-beta as well.

### Security

**Issue-tracker tokens are no longer written into the project file.**
- **Jira:** after a successful connection test the form wrote its credentials a second time — including the API token — into the project. Depending on timing, the token ended up in the `.tara.json` (and with it in the audit repository). The token now stays in the OS keychain only.
- **Azure DevOps:** the personal access token and the OAuth tokens were stored in the project. The PAT is now kept in the OS keychain.
- **Safety net:** before any project file is written — save, export, audit commit — secret fields are removed from the integration settings. A file that still contains a token is cleaned the next time it is saved.
- **Secret scan in audit repositories:** a second TARAflow-managed git hook (`pre-commit`) blocks a commit of a project file that contains a token or password — also for commits from the console. It names file and line, never the value. The Audit tab offers the hook update for existing audit repositories.

### What you should do

1. Open each project that was connected to Jira or Azure DevOps and save it once.
2. **Revoke** the Jira API tokens / Azure DevOps PATs that were used, and create new ones (Atlassian: Account settings → Security → API tokens; Azure DevOps: User settings → Personal access tokens). Tokens that were committed to an audit repository stay in its history until revoked.
3. Run the connection test again in the Integration tab; the new token goes into the OS keychain.
